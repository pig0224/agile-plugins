# /agile:review — 验收汇总与门禁

先阅读 skill `sdd-tdd-method`。**分工例外声明**：本命令在主会话直接执行、不委派 subagent——验收结论来自与用户的会话交互，subagent 拿不到（SKILL 分工红线中「个别命令文件显式声明的例外」）。

**硬规则：AI 只记录、格式化与判定门禁，不代替任何角色的验收动作**——交叉验收、AC 验收的结论必须由相应角色（人工）做出。

## 流程

1. **前置校验**：`process-docs/<编号>/run-test.md` 存在且结论非「不通过」——技术验收先行，失败即停并提示先走 `/agile:run-test`。
2. **读验收矩阵**：review.md 已有内容（验收项/验收人/环境/结论）；缺失时按 SOP 验收矩阵生成骨架。
3. **收集结论**：向用户逐项收集——交叉验收（前端验后端接口、后端验前端页面）、AC 验收（产品逐条确认 requirement.md 的 AC）、独立测试执行（如有）；只登记人给出的结论，未验收项如实标「未验收」。
4. **写 review.md**：验收矩阵（验收项/验收人/环境/结论/时间）+ 未闭环清单。
5. **门禁判定**：
   - 全部通过 → 输出「✅ 可交付 PR」，提示走交付（PR 描述含编号）与 `/agile:release`
   - 有未闭环 → 列出清单，明示**不得交付 PR**；缺陷类未闭环建议 `/agile:fix-bug` 修复后重走 run-test 与对应验收
6. **轻量通道降级**：STO 轻量 / BUG / OPS（判定见团队 SOP「轻量通道」节）review 降级为**一行验收确认记录**——报告人确认修复生效（BUG）/ 提需求人确认（STO 轻量）/ 负责人自查（OPS）+ 确认时间，写入 review.md，不强制矩阵（替代豁免声明，保留验收痕迹）。

## 产物

`process-docs/<编号>/review.md`：验收矩阵 + 未闭环清单 + 门禁结论（可交付 / 不可交付）。

## 原则

- 诚实原则：未验收不标通过；结论只登记人给出的内容。
- 验收串行；验收期才写 review.md（SOP 规则）。
- 产物全中文。
