# /agile:release — 发布前置检查与记录

先阅读 skill `sdd-tdd-method`。**分工例外声明**：本命令在主会话直接执行、不委派 subagent（SKILL 分工红线中「个别命令文件显式声明的例外」）。

**硬规则：本命令不执行任何发布动作**——合并 PR、部署、发版一律人工执行（SKILL 提交红线「决不允许发版」的流程内延伸）。本命令只做前置检查、记录起草与结果登记。

## 流程

1. **前置检查**（只读）：
   - review.md 门禁结论为「可交付」（缺失先走 `/agile:review`）
   - run-test.md 结论非「不通过」
   - PR 已合入 main——向人工确认（AI 不操作 git 远端）
2. **起草 release.md**：
   - 版本/变更清单（从 PR 与任务文档提炼）
   - **回滚方案**（必备要素：回滚目标、回滚步骤、数据影响与处理、回滚后验证点——按本次变更内容起草，不得敷衍为「回滚上个版本」）
3. **明示人工执行**：输出「请人工执行合并/部署」与前置检查结论；等待人工完成。
4. **发布后登记**：人工确认完成后，记录部署时间、环境、验证结论 → 闭环。
5. **收尾提醒**：`agile worktree remove feat/<编号>`（主工作区执行）。
6. **轻量通道降级**：STO 轻量 / BUG / OPS 涉及部署时 release.md 记一行（变更 + 回滚点），不强制完整要素。

## 产物

`process-docs/<编号>/release.md`：前置检查结论、变更清单、回滚方案、发布记录（时间/环境/验证）。

## 原则

- 发布顺序不变：合并先于发版（main 始终等于生产在跑的代码）。
- 诚实原则：未执行/未确认的步骤如实标注。
- 产物全中文。
